# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — runs Vite dev server (port 9777) and `tsc --build --watch` together. `dev:scan` adds react-scan via the `scan` mode.
- `npm run build` — production build to `dist/`. Also emits `tmp/bundle-visualizer.html`.
- `npm run preview` — preview production build (port 9111).
- `npm run tsc` — one-shot type-check.
- `npm run lint` — runs eslint, stylelint, and prettier checks in sequence. Individual: `lint:eslint`, `lint:stylelint`, `lint:prettier`.
- `npm run fix:prettier` — auto-format.
- Node `>=22` and npm `>=10.9.0` are required (yarn is blocked). Husky runs commitlint (`@commitlint/config-conventional`) on commit-msg.

There is no test runner configured in this repo.

## Architecture

This is a Vite + React 19 + TypeScript SPA template using **TanStack Router** (file-based, code-split), **TanStack Query**, **TanStack Form**, **wagmi + RainbowKit + viem** for Web3, **Base UI** primitives, **ky** for HTTP, and **Zod** for schemas. The React Compiler is enabled via `babel-plugin-react-compiler`.

### Layered structure (the load-bearing one)

The codebase enforces a strict layering between routes → modules → components/ui:

- `src/routes/` — TanStack Router file-based routes. **Routes only render modules**; they must not import from `src/components` or `src/components/ui` directly. Lazy routes use `<route>.lazy.tsx`; pair a non-lazy `<route>.tsx` next to it when you need `validateSearch` / `beforeLoad` / `loader` (use `noopReturnNull` from `src/lib/utils/noopReturnNull.ts` as the component on the non-lazy half). Layouts live as `_<name>-layout.tsx` + folder, with the layout component implemented in `src/components/layouts/<Name>Layout/`.
- `src/modules/<Name>/` — page-level features (one per route). Same folder anatomy as components, plus may own `hooks/`, `components/` (sub-modules), `context/`, `schemas`, etc. Modules take **no props**.
- `src/components/<Name>/` — shared components that may contain business logic.
- `src/components/ui/<Name>/` — primitives without business logic (Button, Input, Tabs, etc.). These wrap **Base UI** (`@base-ui/react`) primitives following a co-located `index.tsx` + `styles.module.css` + `types.ts` pattern with CSS Modules and `clsx`-composed variants. Re-export Base UI prop types from `types.ts`.

Each component/module folder follows the same anatomy: `index.tsx`, optional `styles.module.css`, `types.ts`, `hooks/`, `utils/`, `constants.ts`, `schemas.ts`, `regexps.ts`, `context/`, `components/`. Hooks/utils/contexts are scoped to their folder and **may not** be imported from outside that scope — promote them to `src/hooks` / `src/lib/utils` / `src/contexts` if reuse is needed.

### Services & data fetching

`src/services/<feature>/` contains: `api.ts` (ky calls), `queryKeys.ts` (hierarchical key factory), `queries.ts` (queryOptions/mutationOptions and hooks), `types.ts`. Pattern:

- Query keys are a factory object (`FOO_QUERY_KEYS.all` → `.list()` → `.listWithParams(params)`). Query keys may be imported anywhere for invalidation/prefetch.
- Define `queryOptions(...)` / `mutationOptions(...)` factories first, then thin `useXxx` hooks wrap `useQuery(getXxxQueryOptions(...))` / `useMutation(xxxMutationOptions())`.
- Query hook arguments are passed positionally, not as objects.
- `src/lib/@queryClient.ts` and `src/lib/@http.ts` hold the global QueryClient and ky instance.

### Configuration / globals

- `src/lib/` — global app glue: `@http.ts`, `@queryClient.ts`, `wagmi.ts`, `constants.ts`, `schemas.ts` (incl. `envSchema`), `regexps.ts`, `types.ts`, `utils/` (`checkEnv`, `focusFirstError`, `noop`, `noopReturnNull`, `sleep`, `auth/`).
- `src/main.tsx` — wraps the app in `WagmiProvider` → `QueryClientProvider` → `RainbowKitProvider` → `RouterProvider`. Calls `checkEnv(envSchema)` on boot.
- `src/routeTree.gen.ts` — auto-generated by `@tanstack/router-plugin`; never edit.
- `src/vite-env.d.ts` — must be updated when adding env vars; mirror them in `envSchema`.

### Path aliases (vite.config.ts + tsconfig)

- `@/icons/*` → `src/icons/*` — SVGs imported as `import Foo from '@/icons/foo.svg?react'` become React components via `vite-plugin-svgr`. The `?react` suffix is required. Color via CSS `currentColor`.
- `@/*` → `src/*` for everything else.

### Route API hook convention

For each module, create `src/modules/<Name>/hooks/use<Name>RouteApi.ts` that wraps `getRouteApi('/<route>')` and re-exports `useSearch` / `useNavigate`. This avoids re-iterating the route tree and lets the `from` be set once per module.

### Styling

- TailwindCSS-style utilities are not configured; styling uses **CSS Modules** (`styles.module.css`) with design tokens from `src/styles/index.css`. Use `clsx` for conditional classes and data-attributes (e.g. `data-variant`) for Base UI variant styling.
- Stylelint enforces standard config; run `npm run lint:stylelint`.

### Icons

SVGs live in `src/icons/` with kebab-case names. Compress with SVGOMG before committing. Import with `?react` to get a React component accepting standard `SVGProps<SVGSVGElement>`.

### Notes for future edits

- Don't add tests/test runner unless asked — none exists.
- Don't introduce a global `src/utils/` or `src/constants.ts` at the root unless a util is genuinely cross-cutting; the convention is to keep things scoped to the smallest folder that uses them and only promote on actual reuse.
- `npm run knip` is mentioned in the README but not present in `package.json` scripts — don't rely on it.
